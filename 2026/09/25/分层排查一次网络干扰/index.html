校园网 WLAN 直连（无代理）下对 Cloudflare 相关入口做了分层测量，时间 2026-09-21 至 09-22。工具：curl 8.21、Python 手工构造 TLS ClientHello / DNS 报文，以及 PowerShell 网络 cmdlet。结果覆盖 DNS 注入、SNI 匹配与共享 anycast 连坐三类机制，并与审查测量文献中的参数对照。数据来源为本机抓包与查询记录，未做交叉验证的推测在文中单独标明。

环境

项 值
默认网关 / 本地 DNS 192.168.1.1，OpenWrt + smartdns
网卡 DNS WLAN → 192.168.1.1；以太网 → 119.29.29.29 / 223.5.5.5
IPv6 仅 ULA（fde9::/48），无全局地址、无 ::/0
代理 无。环境变量无 HTTP(S)_PROXY，curl 加 --noproxy '*'

网关对境外域名不下发 AAAA；dns.alidns.com DoH 可返回 www.cloudflare.com 的 AAAA（2606:4700::6810:7b60）。IPv6 通道不存在，绕行路径不成立。

归属

观测 结论
www.cloudflare.com / blog / developers / speed / api 200 / 301，服务端正常应答
github.com 直连 200
自有直连入口 xcdn2.xiey.work 200
不存在域名 网关返回 NXDOMAIN，无门户劫持
www.google.com → 31.13.92.37 Facebook 地址段，注入型假应答
workers.dev → 轮换假 IP 池 每次查询不同（185.45.7.165、104.244.43.231…）
被封对象 google / youtube / x.com / wikipedia / cloudflare-dns.com / workers.dev / 1.1.1.1

被封名单为全国性目标。假 IP 注入落在 Facebook 地址段，属注入型应答的典型特征，与 Hoang et al. 的系统测量一致[1]。DoH 动态封锁与 net4people #68 的记载一致[2]。本地网关只做转发、不改写应答。归属为路径上的审查设备（GFW），不是校园网自有策略。

DNS

真值对照用 doh.pub / dns.alidns.com。

域名 本地 DNS 真值
www.cloudflare.com 104.16.133.229 一致
workers.dev 轮换假 IP 池 104.18.12.15 / 104.18.13.15
www.google.com 31.13.92.37（假） 142.251.151.119 等

通道矩阵（目标 1.1.1.1，除非另注）：

通道 行为
UDP 53 丢包
TCP 53，良性名 通，返回真值
TCP 53，被针对名（google / youtube / workers.dev） 建连后 0.07–0.23 s 被 RST
DoH → doh.pub、dns.alidns.com 200，稳定
DoH → cloudflare-dns.com、dns.google、dns.quad9.net、doh.mullvad.net 等 无响应
DoT 853 → 1.1.1.1 首次查询成功（合法证书、正确应答），随即 RST，40 min 未恢复
DoT 853 → 9.9.9.9 / 8.8.8.8 超时

封锁键在 DNS 层是查询名，不是传输协议本身：同一 TCP 53 上良性名通过、被针对名被 RST。假 IP 可通过更换上游消除（doh.pub / dns.alidns.com 均返回真值），属配置改动；被封 SNI 仍需 TLS 层处理。

SNI

对照方法：同一可达 Cloudflare anycast IP，TCP 建连后发手工 ClientHello，只改 SNI，以是否收到 ServerHello 为判据。记录分片 = 将 ClientHello 拆成 ≥2 条 TLS 记录（切割点落在 SNI 主机名内部或扩展边界）。

SNI 单条记录 记录分片 TCP 段级分段（15 ms 间隔）
www.cloudflare.com 通过 通过 —
cloudflare-dns.com 阻断 6/6 通过 9/9 —
one.one.one.one 阻断 4/4 通过 8/9 —
自有入口（两个边缘 IP） 阻断 4/4 通过 5/5 —
www.google.com 阻断 2/2 通过 2/2 —
*.workers.dev 阻断 阻断 0/15 —
www.youtube.com / x.com / www.wikipedia.org 阻断 阻断 0/2 each —
（对照）同一 TLS 记录拆两个 TCP 包 — — 0/9，无效

同一 IP 上更换 SNI 即可复现或解除阻断，封锁键是 SNI。审查设备重组 TCP 流，但不按 TLS 记录边界重组；RFC 允许握手消息跨记录，服务端（nginx/OpenSSL）零改动。TCP 分段无效、TLS 记录分片有效，差在匹配发生的层。该绕过路径与传输层混淆分析[3]、TLS 记录分片研究[4]描述的匹配规则一致。

分片不是通用绕过：*.workers.dev 15 种变体全部失败，说明该名单另有更强规则或独立匹配路径。Cloudflare 社区已有对应讨论[5]。www.google.com 分片仅证明 DPI 放行；其真实 IP 段（142.251/172.217）TCP 443 本身不可达，分片解决不了 IP 层。

共享 anycast 连坐

Cloudflare 边缘为共享 anycast。对照实验（104.19.193.29）：

  1. 良性请求 api.cloudflare.com → 301；
  2. 向同一 IP 发一次 DoH 形态查询（SNI cloudflare-dns.com）→ 失败；
  3. 立即重发良性请求 → 超时（对照 IP 同时段正常）；
  4. 约 8 min 后恢复 301。

机制是本机或局域网内任意进程触发一次被针对查询，该 IP 上全部站点被连坐 5–8 min。这解释了 CF 入口与自有入口的间歇性失败。时长与 net4people #68 记载的 “5 minutes” 同量级[2]。

探测副作用一例。会话内对自有入口发过未认证 WSS / 被封 SNI 探测后，该 SNI 在两个边缘 IP 上均被掐断（TCP 可连、握手超时），观测窗口内未自愈。因果无法在网络内侧证明，时间相关性成立。对该入口的主动探测应默认为已触发阻断。

无效路径

路径 结果
域前置（良性 SNI + 目标 Host） CF 边缘 403
备用端口 8443/2053/2083/2087/2096 连接可达，被针对 SNI 仍 RST
ECH 目标 HTTPS RR 无 ech 参数（id=5），未部署[6]
QUIC / HTTP3 UDP 443 无回应；QUIC 握手内 SNI 已被针对性处理[7]
DoT 首通后即封
WARP 数据面（2408、UDP 53/443） 不通；控制面 engage.cloudflareclient.com:443 可达（403）
IPv6 绕行 无全局 IPv6，网关不下发境外 AAAA

文献对照

以下参数直接取自论文，不作延伸推断。

Wu et al.[8] 提出 GFW 对全加密协议的连接级被动检测：只看客户端首包，按五条豁免规则判定，全不豁免才封。Ex1 熵 len×4/popcount 脱离 [3.4, 4.6]；Ex2 前 6+ 字节全可打印 ASCII；Ex3 可打印占比 >50%；Ex4 连续可打印 >20 字节；Ex5 命中 TLS/HTTP 指纹。本项目首包为 uTLS Chrome ClientHello，命中 Ex5，同时结构化低熵命中 Ex1，双重豁免。

Xue et al.[9] 的度量为 Δ = ARTT − TRTT。直连时 Δ ≈ 服务端处理时延（毫秒级）；代理会话两层错位，Δ 额外包含代理→源站整段距离，跨境 50–300 ms，协议无关。论文告诫 naive 延迟遮蔽会反噬。按该文实现 θ-SPRT 检测器（θ0=0.95，θ1=0.50，T=15 ms，边界 ±ln100，MIN_WINDOWS=4，效度门=任一直连对照判 PROXY 则整份作废），判决参数开抓前冻结。预注册红蓝结果：

条件 强 PROXY 流 >T 占比 p90 Δ 判决
基线（微应答关闭）n=2 每重复 1 条 28–60% +90～+116 ms logLR +8.8～+11.3，定罪
微应答整形后（生产 S1） 0 5–10% +6～+13 ms 可分析大流 4/4 判 direct
真实直连对照 0 0% ≈0 θ̂=1.000，零误判

残差约为基线的 1/6–1/8，未归零。按论文 direct 类先验 θ0=0.95，代理流落在边缘；更长观察窗或更小 T 理论上仍可区分。

Ablove et al.[10] 对泄露防火墙源码做实现级分析：封锁路径存在可指纹化的固定实现特征。自有协议侧对应避免固定魔数、固定头序。

Dunna et al.[11] 表明未公开 Tor bridge 同样被 DPI + 主动探测覆盖，扫描形态为建连后发数据。TrojanProbe[12] 用构造 HTTP 请求指纹化服务端实现。针对未授权探针的标准应答是返回完整站点并 redirect 到真站。

Fifield & Tsai[13] 测得从可发现到被封为 2–36 天，且常在客户端软件发布后触发。

Mehta et al.[14] 的侧信道整形放在 guest 外部，与流控/拥塞/重传信号解耦。若继续做 Δ 整形，该分层是不破坏 TCP 语义的参考。旧 VMess 的 MD5 头部/认证弱点[15]同样属实现指纹问题。

结论

测量得到的封锁键按层分离：DNS 层是查询名（假 IP 注入 + TCP 53 上按名 RST），SNI 层是 ClientHello 中的名字（同一 anycast IP 上更换 SNI 即可复现或解除阻断），共享 IP 上的连坐窗口为 5–8 min。TLS 记录分片可绕过部分 SNI 匹配（cloudflare-dns.com 9/9、自有入口 5/5），对 *.workers.dev 无效（0/15）；TCP 段级分段无效（0/9），匹配发生在 TLS 记录边界而非 TCP 流重组之后。时延层在微应答整形后，θ-SPRT 判决级与直连不可区分（基线强 PROXY 流消失，真实直连零误判），Δ 残差为基线的 1/6–1/8，未归零。IPv6、域前置、备用端口、ECH、QUIC、DoT、WARP 数据面均无可用通道。
